# WatchDrip+ (Zepp OS) - Анализ Архитектуры и Логики

Этот проект является версией приложения **WatchDrip+**, специально разработанной для умных часов на базе **Zepp OS** (таких как Amazfit GTR 3/4, GTS 3/4, T-Rex 2, Xiaomi Smart Band 7 и многих других).

В отличие от Android-версии приложения, которая модифицирует и прошивает бинарные файлы циферблатов "на лету", этот проект представляет собой **нативное мини-приложение для Zepp OS**, написанное на JavaScript. 

## 🎯 Основная логика работы

Приложение получает данные о глюкозе с телефона и отображает их на экране умных часов, используя стандартные элементы пользовательского интерфейса (виджеты) Zepp OS. 

1. **Запрос данных**: Приложение на часах (`page/index.js`) запрашивает свежие данные об уровне глюкозы через определенные промежутки времени.
2. **Side Service (Служба-компаньон)**: Запрос передается по Bluetooth на телефон, где работает фоновый скрипт (`app-side/index.js`), запущенный внутри официального приложения Zepp.
3. **Получение данных на телефоне**: Фоновый скрипт делает HTTP-запрос (через `fetch`) к локальному серверу или API xDrip+ (например, локальный веб-сервер xDrip на телефоне или облачный Nightscout).
4. **Рендеринг UI**: Полученный JSON с данными о глюкозе, трендах и дельте передается обратно на часы, где парсится и отображается на экране (обновляются текстовые виджеты и картинки стрелок).

## 🏗 Архитектура проекта

Структура приложения строго следует стандартам фреймворка Zepp OS (v2/v1):

### 1. Конфигурация (`app.json`)
* Описывает приложение: имя, версия, иконка.
* Запрашивает необходимые разрешения (`data:os.device.info`, `device:os.alarm`, `device:os.ble`).
* **`targets`**: Содержит огромный список поддерживаемых устройств (от `mi-band7` до `trex3pro` и `balance`). Для каждого устройства заданы профили экранов (квадратные, круглые, прямоугольные).

### 2. Модуль часов (`page/index.js`) - Device App
* **Интерфейс (UI)**: Для отрисовки используются нативные виджеты Zepp OS (`hmUI.createWidget`). Создаются виджеты для уровня глюкозы (`bgValTextWidget`), времени замера (`bgValTimeTextWidget`), дельты (`bgDeltaTextWidget`) и графической стрелки тренда (`bgTrendImageWidget`).
* **Жизненный цикл (App LifeCycle)**: Инициализация, фоновая работа и деструктор управляются функциями `onInit`, `build`, `onDestroy`.
* **Фоновые обновления и Будильники**: Чтобы данные обновлялись даже когда приложение свернуто, используется система будильников Zepp OS (`hmApp.alarmNew`). Это позволяет "будить" приложение по таймеру.
* **Локальное хранение**: Данные кэшируются локально в файловой системе часов (`WF_INFO_FILE` через модуль `fs`). Это позволяет быстро отобразить последние известные данные при открытии приложения до того, как они обновятся с телефона.
* Присутствует экран настроек (`PagesType.CONFIG`), где пользователь может изменять параметры в виде прокручивающегося списка.

### 3. Модуль телефона (`app-side/index.js`) - Side Service
* Работает на смартфоне (Android/iOS) внутри приложения Zepp.
* Использует `MessageBuilder` (RPC-библиотеку на базе Zepp BLE API) для общения с часами.
* Обрабатывает команды от часов: `Commands.getInfo` (получить данные о сахаре), `Commands.getImg` (скачать изображение), `Commands.putTreatment` (отправить информацию о лечении/инсулине).
* Выполняет `fetch`-запросы к локальному IP-адресу/URL, где работает xDrip+ или другой источник данных (`SERVER_URL` + `SERVER_INFO_URL`).

### 4. Утилиты и Модели (`utils/` и `shared/`)
* **`watchdrip-data.js`**: Класс-модель для хранения и обработки данных об уровне глюкозы, расчета разницы во времени (Stale data) и определения цветов (красный/синий/белый в зависимости от критичности уровня).
* **`constants.js` / `styles.js`**: Хранят настройки таймеров, константы цветов, координаты и стили виджетов (шрифты, размеры) для отрисовки интерфейса.

## 💡 Вывод
Проект является автономным клиентом для отображения CGM-данных, который элегантно использует возможности Zepp OS (виджеты, BLE RPC, Side App) для интеграции с медицинскими приложениями на смартфоне. Это более современный и официальный подход по сравнению с динамическим патчингом прошивок, используемым на старых поколениях браслетов.
